## 1. ავტომატური ტესტების გაშვება

გაუშვით ყველა ტესტი ტერმინალიდან:
```bash
npm test
```

Watch რეჟიმში ტესტების გაშვება (კოდის ცვლილებებზე ავტომატური გადატესტვა):
```bash
npm run test:watch
```

TypeScript ტიპების შემოწმება:
```bash
npm run typecheck
```

პროდაქშენ ბილდის სისწორის შემოწმება:
```bash
npm run build
```

## 2. 12 კრიტიკული ბიზნეს-სცენარი (`tests/scenarios.test.ts`)

სისტემური პრომპტის 21-ე განყოფილების მიხედვით, დაფარულია შემდეგი 12 სცენარი:

1. **სცენარი 1: ფასის კითხვა**
   - კლიენტი ეკითხება მხოლოდ ფასს. AI პასუხობს ფასს, ბაზაში შეკვეთის დრაფტი არ იქმნება.
2. **სცენარი 2: არარსებული პროდუქტი**
   - `LOOKUP_PRODUCT` აბრუნებს ცარიელ სიას. AI ზრდილობიანად პასუხობს, რომ პროდუქტი არ არის, ფასს არ იგონებს.
3. **სცენარი 3: არასრული ტელეფონის ნომერი**
   - მომხმარებელი აწვდის არასრულ ნომერს (მაგ: `599 123`). `isOrderReady` რჩება `false` და ითხოვს 9-ნიშნა მობილურს.
4. **სცენარი 4: არასრული მისამართი**
   - მომხმარებელი უთითებს მხოლოდ ქალაქს. AI ითხოვს ქუჩისა და ბინის დეტალებს.
5. **სცენარი 5: ყალბი / დუბლიკატი ქვითარი**
   - ქვითარი ხვდება `PAYMENT_REVIEW`-ში. Safety Guard ბლოკავს AI-ის ჰალუცინაციას გადახდის დადასტურებაზე.
6. **სცენარი 6: დუბლიკატი ვებჰუკი**
   - იდენტური `platformMessageId`-ის მქონე მესიჯი მეორედ აღარ მუშავდება (იდემპოტენტურობა).
7. **სცენარი 7: არავალიდური JSON LLM-ისგან**
   - მოდელის მიერ დაზიანებული JSON-ის დაბრუნებისას ჩაირთვება Fallback ტექსტი, ბაზა არ ზიანდება და იწერება აუდიტის ლოგი.
8. **სცენარი 8: ოპერატორის ჩართვა (Human Handoff)**
   - კლიენტის მოთხოვნით იქმნება Handoff Ticket, `aiPaused` ხდება `true` და AI ჩერდება.
9. **სცენარი 9: მარაგის ამოწურვა**
   - ნაშთის არარსებობისას შეკვეთა არ იქმნება და AI ვერ აცხადებს წარმატებულ გაფორმებას.
10. **სცენარი 10: Prompt Injection შეტევა**
    - `SYSTEM OVERRIDE` ბრძანებები არ ცვლის სისტემის წესებს და არ ხდება პრომპტის გაჟონვა.
11. **სცენარი 11: არხების იზოლაცია**
    - Telegram, WhatsApp და Messenger-ის იდენტობები მკაცრად იზოლირებულია, მონაცემები ერთმანეთში არ ერევა.
12. **სცენარი 12: ფასის ავტორიტეტული გადათვლა**
    - რაოდენობის შეცვლისას თანხა და მიტანის ტარიფი თავიდან ითვლება სერვერზე.

## 3. ლოკალური ტესტირება Telegram Polling-ით

თუ გსურთ რეალური Telegram ბოტის შემოწმება ვებჰუკებისა და ngrok-ის გარეშე:
1. ჩაწერეთ `TELEGRAM_BOT_TOKEN` თქვენს `.env.local`-ში.
2. გაუშვით:
   ```bash
   npm run telegram:poll
   ```
3. გახსენით თქვენი Telegram ბოტი და მიწერეთ ქართულად:
   - "გამარჯობა, რა პროდუქტები გაქვთ?"
   - "რა ღირს AirPods Pro 2?"
   - "მინდა შეკვეთა"
4. ტერმინალში დაინახავთ ორკესტრატორის მუშაობას, Tool-ების გამოძახებებსა და პასუხებს.
